# การลงลายเซ็น person context

ทุกคำขอจากฝั่ง VM ต้องแนบ header ระบุตัวผู้ใช้ปลายทาง เพื่อให้ฝั่งกลางแยกข้อมูลและตรวจสิทธิ์ได้ถูกต้อง

## 1. หลักการ

- สร้าง header กลุ่ม `X-Person-*` สำหรับทุก request
- ลงลายเซ็น HMAC ของข้อมูล person context ด้วย secret ที่ได้รับ
- ฝั่งกลางจะตรวจลายเซ็นก่อน แล้วจึงแยกข้อมูลตามผู้ใช้ปลายทาง

## 2. ขั้นตอนฝั่งนักพัฒนา VM

1. รวมฟิลด์ person context ตามลำดับที่สเปกกำหนด
2. คำนวณ HMAC แล้วแนบไปพร้อมกับ header
3. ส่ง request ทดสอบแล้วตรวจว่าได้ข้อมูลของ user นั้นจริง

## 3. ข้อผิดพลาดที่พบบ่อย

- ลำดับฟิลด์ตอนเซ็นไม่ตรงกับสเปก ทำให้ลายเซ็นไม่ผ่าน
- เวลาเครื่อง (clock skew) ต่างกันเกินไปจน token หมดอายุ
- ใช้ secret ผิดสภาพแวดล้อม เช่น เอา key ของ dev ไปเรียก production

## เคล็ดลับ

- เก็บ secret ใน environment variable เท่านั้น ห้าม hardcode ในโค้ด
- เมื่อย้ายเครื่องหรือเปลี่ยน key ให้ทดสอบลายเซ็นใหม่ทุกครั้ง
